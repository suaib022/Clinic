# Feedback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Patients rate doctor visits and lab tests (experience + hospital service), add a typed or voice comment, and get an automatic multi-label category, stored and viewable by the right staff.

**Architecture:** Extend `appointment_feedbacks` with category columns; add `lab_feedbacks` with its own RPC; voice goes browser `MediaRecorder` -> `/api/feedback/transcribe` -> OpenRouter Whisper; classification runs server-side after submit via `gemini-2.5-flash-lite` with keyword-rules fallback. Pure logic in `lib/feedback/`, UI in `components/feedback/`.

**Tech Stack:** Next.js 16 App Router, TypeScript, Supabase (SQL, RLS, RPC), Zod, Vitest + Testing Library, OpenRouter.

**Spec:** `docs/superpowers/specs/2026-11-24-feedback-design.md`

## Global Constraints

- Categories exactly: `positive`, `negative`, `improvement`, `staff`. Sentiment exactly: `positive`, `neutral`, `negative`.
- Input method exactly: `typed`, `voice`. Ratings: integer 1–5.
- Patients speak English only.
- Audio is never stored or logged; max 60 s, max 2 MB.
- Models: STT `openai/whisper-large-v3` (verify id/price in OpenRouter models list at build time); classifier `FEEDBACK_MODEL` env, default `google/gemini-2.5-flash-lite`.
- Online Supabase: do NOT apply migrations to the online project. Local/test DB only. Online apply needs user's explicit yes.
- No commits in this plan's execution unless user approves each commit (identity: Ashrafur Rahman Nihad <ashrfurrr558@gmail.com>, ARN101).
- Feedback submit never fails because STT or classifier failed.

## Review Focus

1. Empty comment, ratings only -> must save, categories `{}`, no classifier call. Tested in Task 3 and Task 5.
2. Comment with only whitespace or >2000 chars -> rejected by Zod with clear message. Tested in Task 5.
3. Classifier returns invalid JSON or unknown tag -> falls back to rules, never throws. Tested in Task 2.
4. Patient submits feedback twice for same visit/order -> second call returns "already submitted", no duplicate row. Tested in Task 1 (SQL test script).
5. Microphone denied or browser lacks `MediaRecorder` -> text box still works, error text shown, no crash. Tested in Task 6.
6. Doctor A opening feedback of doctor B, or technician reading doctor feedback -> RLS denies. Tested in Task 1.
7. Transcribe with no auth or wrong MIME -> 401/400, no OpenRouter call. Tested in Task 4.
